## 1. 检测：现在用什么、策略是什么

### 1.1 模型

| 路由 | Hugging Face |
| --- | --- |
| 中文长文 | `yuchuantian/AIGC_detector_zhv3` |
| 中文短文 ≤200 字 | `…_zhv3short` |
| 英文长/短 | `…_env3` / `…_env3short` |

这是 BERT/RoBERTa 句分类器，二分类 AI vs 人，不是溯源器。Hub 卡片几乎为空，是中文社区常用开源权重，不是 RAID 上排过名的方法。四个权重的 `max_position_embeddings` 都是 512。

### 1.2 策略（代码里真实在跑）

- 语言 + 长度选四个权重之一；中英混合两路取平均（`mixed_strategy: mean`）
- 句级滑窗：中文目标 480、上限 640、重叠 1 句；英文目标 **1400**、上限 **1800**（英文 4 字符约 1 token，480 字窗会浪费长模型容量）
- 块分数按不重复字符加权，得到检测器文档分
- `FalsePositiveController`：文体路由（文学 / 论文技术 / 公文新闻 / 问答）；学术技术默认低/高阈值 **0.35 / 0.88**（文学高阈值 0.92）
- 整篇标 `high_risk_ai` 还要求高分段覆盖够、相邻高分段够，否则只报不确定
- `detection.mode` 是 **`api_first`**：Hive / Sightengine 配置为开，失败不中断，再跑本地雨川。两篇 Word 若日志里 API 无有效分，整篇结论才是纯本地雨川 + FP 控制器，不要写成系统「只跑雨川」

产品已补：可直接上传 `.docx` 和旧版 `.doc`（真 OLE `.doc` 用 LibreOffice 转）；前端展示总块数、疑似 AI 块、每块 AI 率。启动脚本：`scripts/start_workbench.sh`（API **8001**，Dashboard **8501**，因 8000 已被占用）。

### 1.3 两篇文档实测（默认窗、检测器阈值 0.8；学术技术高阈值 0.88）

| 文档 | 块数 | 疑似 AI 块 | 整篇加权 |
| --- | --- | --- | --- |
| 《基于AI的自动化漏洞挖掘与攻击向量生成技术》 | 59 | 23 | ~0.61（未过文体高阈值，结论偏 human/uncertain） |
| 《交通运输多模态AI对抗用例…_v4》 | 34 | 0 | ~0.32 |

对照用户给的商业器口径（93/24、45/2）：AI 块数第一篇接近，切块粒度对不上。高分块集中在公式、PoC、状态机等「很顺的技术套话」——BERT 检测器的老问题。段落当块会虚高，不能当复现口径。

整篇 0.61 仍不是 `high_risk_ai`，主因不只是「0.61 &lt; 0.8」：学术技术高阈值 **0.88**，还要高分段覆盖 ≥0.3、相邻高分段 ≥2。这是控制器故意偏保守。

### 1.4 检测相对文献

监督 BERT 仍能用，但是 2023 主路径；RAID 级攻击和未见生成器上最容易被打穿。零样本统计（DetectGPT / Fast-DetectGPT / Binoculars）可当对照分支，不替换主结论。检测产品形态（分块 + 校准 + 拒判）不落伍；底座偏旧。RAID 对抗集在配置里仍是 `enabled: false`。

**检测主路径建议：继续用雨川交差。** 不要把检测器接到溯源头上。

## 2. 分块很多、单块 80 多、阈值 88/92：会不会进不了溯源？

会，而且当前代码里其实是 **三套不同门槛**，页面数字容易让人以为「块数很多就该判 AI、就该溯源」。

### 2.1 三套门槛（必须分开说）

| 你在页面上看到的 | 实际规则 | 配置 |
| --- | --- | --- |
| **疑似 AI 块** | **单块**分数 **&gt; 高阈值** 才计数。80 多不够。学术技术高阈值 0.88；文学 0.92 | `domain_thresholds.*.high_threshold`；前端 `segment_verdict` |
| **整篇检测结论** | 先看各 provider 分数的**中位数**相对低/高阈值，长文还要：高分段覆盖 ≥0.3、相邻高分段 ≥2、有效覆盖 ≥0.7。否则 `uncertain` / `low_risk`，即使很多块是 0.80 | `FalsePositiveController` |
| **要不要跑家族溯源** | `detection.score >= deep_provenance_threshold`（默认 **0.6**）。**不看** `high_risk_ai` 这个标签 | `detection.deep_provenance_threshold`；`ProvenancePipeline` |

因此：

- 59 块里 23 块「疑似 AI」、整篇加权 0.61、结论仍不是高风险 AI：**符合设计**，不是 bug。
- 0.61 ≥ 0.6 时，**标签可以是 uncertain，溯源仍可能被触发**（水印走 deep 门；文本归因同样看 `deep_triggered`）。
- 若整篇分落到 0.6 以下（第二篇 ~0.32），归因会 `skipped`，即使个别块偏高。

`detection.score` 在开了 FP 控制器时，是 **provider 分数的中位数**（本地雨川通常就一路，约等于检测器的字符加权文档分），**不是**「疑似 AI 块占比」。

### 2.2 现在的溯源怎么切文本？

**代码现状（已改）：复用检测块，逐块（相邻才合并）跑切窗 A0 seed42 + B0 + B1 + B3 等权融合。**

工作台生产头是 `window_a0_equal_fusion`。seed62 只作对照，不加载。不再训 A1–A4。

当前产品形态是：

```text
检测：分块打 AI 率  →  整篇标签（严）
溯源：整篇一个 Top-K（要 score≥0.6），超长则截开头
```

混写文档里，整篇 Top-K 会被「像人的段落 + 像 AI 的套话」平均掉，后面的高分块可能根本没进模型。

### 2.3 敲定的产品口径（2026-09-09 已接到工作台）

检测继续分块。**不要用「每一块都过 0.88」当溯源开关**，也不要把不相邻的高分块粘成一篇假长文再切。

**开关（长文满足任一即可）：**

1. 整篇加权 AI 率 ≥ `deep_provenance_threshold`（现有 0.6），或
2. 高分段覆盖（块分 &gt; 0.88 的字符占比）≥ 0.15，或
3. 疑似 AI 块 ≥ 2

短文仅 1 块：块分 ≥ 0.35 允许溯源；≥ 0.88 才整篇钉 `high_risk_ai`。不用「疑似 AI 块占比」当唯一门。

**吃什么：复用检测块，逐块溯源，相邻才合并。**

1. 单位 = 检测块（同一 `start/end`），不再另切全文。
2. 入选：先取块分 &gt; **0.88** 的块；不够再按分数补 &gt; **0.35**，上限约 8～12 块。
3. 原文里连续（或仅重叠）的高分块拼回一段；**不相邻的不要拼**（agent 段和玩具段不要进同一个 512 窗）。
4. 每一段单独做家族 Top-K。单块通常 ≤640 字，中文塞得进 512；只有同一话题的超长连续段才在段内再滑窗。
5. 总结论 = 各块按块长（或块长×检测分）加权平均 Top-K，允许 `unknown`。

**页面只展示：**

- 每一个进入溯源的块的 Top-K
- 一条总加权结论

不展示「覆盖了全文百分之几」（可留日志）。policy 里已有 `exact / family_only / unknown / abstain`，对外三级仍是：`人 / AI-家族明确 / AI-家族不明`。

**不要做：** 把分散高分块合并成 `suspicious_pack` 再横切 512——接缝会把不同话题粘在一起，比逐块伤得更大。

## 3. 多家族溯源：现在用什么、效果怎样

任务：闭集 **10 家族**（每家 fast / balanced）：openai、claude、gemini、deepseek、qwen、glm、minimax、kimi、doubao、mimo。  
数据：智增增网关 `zhizengzeng-attribution-server-6k-v5.jsonl`，清洗后约 5686 条。冻结 train/val/test，筛选不碰 test。

### 3.1 神经主干与配方

- 入选：`FacebookAI/xlm-roberta-base`，512 token，线性头（N0，8-seed val macro-F1 0.557）
- mDeBERTa-v3、CANINE 8-seed 整体不如 N0
- A0 纯家族分类胜出；辅助模型头 / 对比学习 / 三窗口（A4）过不了 +1 个 macro-F1 的门
- **训练时长文处理：** A0 对超过 512 token 的部分 **直接截断丢掉**（`truncation=True`），一条 JSONL 仍是一条样本。A4 是同一条上取头/中/尾最多 3 窗再融合，**不是**把一篇切成 3 条独立训练数据。v5 约 5738 条，completion token 中位 1096；若按非重叠 512 切窗，窗条数合计约 **2.06 万**（篇均 3.6），但同一篇的窗高度相关，不能当成 2 万篇独立作文。这叫「窗级扩增」，**还没做过**；A4 失败不能用来否定它。产品第一刀不改训练集。

### 3.2 经典支与融合

| 实验 | 做法 | val macro-F1 |
| --- | --- | ---: |
| B0 | 字符 TF-IDF + Logistic | 0.557 |
| B3 | 词+字符 TF-IDF + 校准 LinearSVC | **0.582**（test 同） |
| E1 | A4 + B0 + B1 概率融合 | **0.646** |

Phase4 没把最强的 B3 接进融合。

### 3.3 E1 数字（8-seed 验证，未看 test）

| | Acc | Macro-F1 | 最差家族 F1 | 换版本迁移 F1 |
| --- | ---: | ---: | ---: | ---: |
| A0 | 0.58 | 0.56 | 0.20 | ~0.37 |
| A4 | 0.60 | 0.59 | 0.22 | ~0.39 / 0.38 |
| **E1** | **0.67** | **0.65** | **0.31** | **~0.47** |

分家族：doubao 0.98、openai 0.88 稳；**glm 0.35、mimo 0.33、deepseek 0.51** 拖后腿。  
拒识目标 precision≥0.9 / coverage≥0.4 / ECE≤0.05 **未达到**。仓库结论：E1 可当研究模型，**不能当部署硬标签**。

配置里还有 OpenTuringBench 原型、n-gram 原型、自训 joblib；LLMDet 默认关。文本水印关着（网关生成无跨厂商水印）——这是对的。

仓库已有、但训练尚未完全当产品用的两层：

- 规范样本：`provenance/text_attribution_schema.py` 的 `AttributionSample`
- 决策：`provenance/text_attribution_policy.py` 的 `exact / family_only / unknown / abstain`

原始 dump 字段是网关日志（`family_id`、`request_model`、嵌套 `prompt`），和规范层不是同一张表。研究训练另有 `research/text_attribution/training_data.py` 里同名 `AttributionSample`，当前 Phase1–4 走的是这一套。

## 5. 对照「另一份 2026 谱系列表」

那份材料里的论文大部分能检索到（USENIX Security 2026 文生图父模型、LLM DNA、AWM、SeedPrints、Stemma、IncreFA / LIDA 等）。本机 Playwright 仍可能拦 GitHub/arXiv 网页；服务器 `curl` 已能打开部分摘要页。

四层划分本身没错。和本横向项目同层的是 **内容级归因**。谱系论文的输入是 checkpoint 或对模型发 probe，不是用户 Word。不要把主方案改成 DNA / 权重指纹。可借的思想是图侧的增量 / 检索式注册：文本侧最小对应物就是 `unknown` + 新家族进 zoo。

## 6. 结论：方案对，继续走；优化细节，不换赛道

横向目标：「不断有新模型，但只要有数据集就能更新分类器」——这已经定义成 **可增量的内容分类器**。能溯源的范围 = 库里有样本的那些家族。

### 6.1 流程上该补（比换模型更值）

1. 对外三级：`人 / AI-家族明确 / AI-家族不明`
2. 新家族进 zoo 的规程：样本下限 → 加类 → 整头重训；同时留原型向量
3. **把 B3 接进融合**
4. 验收固定：闭集 F1 + 未见家族当 unknown + 换版本（已有 0.47）+ 有余力再加轻量改写
5. **溯源门不要绑死文体高阈值 0.88/0.92**；复用检测块逐块溯源，相邻才合并；页面为每块 Top-K + 总加权（见第 2.3 节）

### 6.2 分类模型：可试，过门才换

- 不要再给 XLM-R 加 A5/A6 损失
- 不要 6k 全参训 7B
- 不要单 seed 晋级
- 可试：冻结多语句向量（E5-large / GTE / bge-m3）+ 线性头或原型检索
- softmax 头和原型库可并存

### 6.3 训练：治难类和版本偏移

- 专剖 glm / mimo / deepseek
- fast/balanced 当域偏移做进训练
- 雨川检测器不接到溯源头

### 6.4 明确先别动

- 检测主路径
- LLM DNA / AWM / Stemma / 文生图父模型（合同变成「审计权重」再拉）
- GPT-as-judge 当主分类器
- 解冻 test 选模型

## 7. 数据质量差、下一批格式又不一样：怎么办

**不要靠换分类模型解决。** 那是采集/入库问题。

```text
任意来源 dump
  → adapter（每个数据源一个，只做字段映射）
  → AttributionSample 规范样本
  → 质检门（不过门不进 train）
  → 按 prompt_group_id 切分（已有，防泄漏）
  → 重训分类器 / 往原型库插新家族
```

质检建议：空/过短/拒答丢弃；缺 family 或对不上 catalog 丢或隔离；`request_model` 与 `response_model` 不一致（已有 `route_mismatch`）丢或降权；同一 prompt 组必须同 split；字段对不上规范 = adapter 失败，**禁止改训练脚本迁就 dump**。

## 9. 一句话

检测：雨川 + 滑窗 + 文体阈值，继续交差。疑似 AI 块用高阈值计数；整篇结论更严；溯源另看 0.6 的 deep 门，二者不是同一把锁。  
溯源：工作台已改成 **逐高分块 Top-K + 总加权**，不相邻块不粘贴；正式权重是切窗 A0 seed42 等权融合 B0/B1/B3。允许 unknown。窗级扩增（复制 family_id 把长文切成多条）已用于 A0 训练，不是 A4。  
赛道对；生产融合是切窗 A0+B0+B1+B3 等权（seed42）；补拒识、加类规程、规范数据层。  
2026 谱系/DNA 是「模型的爹」，不是「这段字的爹」。  
数据换皮用 adapter，数据变脏用质检，不要为此换范式。
