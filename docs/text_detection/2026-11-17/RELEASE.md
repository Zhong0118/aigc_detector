# 高召回文本筛查服务更新

用户已明确选择“优先检出 AI，接受更多可疑、需复核结果”。本轮以识别并展示可疑线索为目标，保留严格确认阈值。

## 实际变化

用户原文不进入训练、模型校准或第三方生成请求。对同一份 3,531 字符报告：

| 项目 | 原服务 | 新服务 |
| --- | --- | --- |
| 文档模型风险分数 | 0.2037 | 0.8780 |
| 严格判定 | low_risk | uncertain |
| 用户可见结论 | 未明显检出 | 疑似 AI，需复核 |
| 达到 0.8 提示阈值的窗口 | 原结果无对应提示 | 6 / 8 |

这不是把“uncertain”强行变成“已确认 AI”：新版模型的输出改变了，并新增了明确的筛查提示。87.80% 是风险分数，不是文章中 AI 撰写的字符比例。高分窗口用于定位复核内容，严格确认仍使用独立校准阈值。

## 模型与数据

实际部署模型为 `20261117-mdeberta-v1`：基于服务器缓存的 [Microsoft mDeBERTa-v3-base](https://huggingface.co/microsoft/mdeberta-v3-base) 定向微调，标签 0=human、1=ai。该底座模型卡标注 MIT 许可证。训练 7,310 篇，最后四层编码器及分类头参与训练，按验证集 AUROC 选择第 2 轮权重。

训练来源为 HC3、M4 与项目此前采集的现代模型输出。按原题目/文档和重复文本分组隔离训练、验证、校准与测试。训练窗口按文档平衡；推理覆盖全部 tokenizer 溢出窗口，文档仍使用字符覆盖加权。混合语种使用主导语言分支，避免英文缩写让中文报告被英文模型分数稀释。

另生成 12 篇不同题目的 4,000 字级报告，用于后续候选的长文适配和测试，未包含用户原文或量子密码主题。长文补训、扩大生成模型覆盖、完整编码器训练等候选没有在这份已知报告上取得更稳定结果，因此未部署。所选检查点不使用这些新增长报告训练。

所有模型候选结果都保留在服务器 `models/text_binary/` 与隔离验证目录中；未通过这一回归的模型没有被描述为成功修复。用户原文是已知开发回归，不是盲测样本。多轮使用同一批测试分组比较候选会产生选择偏差，正式泛化验收仍需新一批数据。

## 本轮测试结果

冻结模型后，在 3,947 篇测试文本上通过实际判定器计算，包含 2,347 篇 AI、1,600 篇真人文本：

| 口径 | AI 被提示比例 | 真人被提示比例 |
| --- | ---: | ---: |
| 高召回筛查：严格高风险，或风险分数 ≥0.8 的 uncertain | 2,310 / 2,347 = 98.42% | 245 / 1,600 = 15.31% |
| 严格高风险判定 | 2,160 / 2,347 = 92.03% | 21 / 1,600 = 1.31% |

筛查口径下，约 15% 的本轮真人样本也会进入疑似 AI 复核，不能把疑似标签直接作为最终定性。中文与混合语种分别以 1,099 与 220 篇留出真人文本校准；另 3 篇纯英文校准样本未用于中文阈值。公开的误报率与召回率来自测试分组，不使用选择检查点的验证集来冒充独立性能。

总体长文真人样本仍偏少；不能把本轮问答/百科为主的成绩等同于所有学术报告的效果。OpenAI 的较新版本只在现代采集数据中保留作测试，训练仍包含旧 ChatGPT，不能宣称整个 OpenAI 家族未见。证据见 `release-summary.json`、`release-thresholds.json` 和 `release-training_metadata.json`。
