# 文本漏检修复与评测结果

这是首轮排查记录；后续重训、筛查策略与服务更新见 [上线记录](RELEASE.md)。

日期：2026-11-17。代码基线：`2b37c811f7787beba8e570cf4d5bac9b1ef27b30`；线上实例基线：`6cec92a5d8b2656cae49b2d79f17dee638d870bf`。

## 结论

已修复分类器窗口静默截断，建立可重复运行的对照评测，并防止新版评分沿用旧校准的验证指标。用户报告 98 的漏检仍然存在，不能宣称已解决识别能力问题。

当前证据不支持从零训练，也不支持直接改成取最大值或降低阈值。保留完整 token 覆盖作为正确性修复；下一阶段应补足与用户长报告匹配的真人/AI 数据，对比候选检测模型与现有模型的定向微调。当前对照集用于探索，不能同时充当后续模型选择和最终验收集。

## 修复内容

- 继续使用原有句子窗口、原文坐标和文档聚合；每个分支在内部按 tokenizer/模型/配置的最小 token 上限分窗。
- 所有溢出 token 均参与推理；按有效 token 数加权，排除 padding 和特殊 token。
- 分数协议标记为 `token-complete-v1`。与校准文件的协议不匹配时，清空旧误报率、召回率、AUROC 和对应样本计数，展示“需重新验证”的说明；不伪造新指标或改变阈值来通过单篇样本。
- 既有校准脚本重新生成产物时会保存实际使用的评分协议，只有匹配协议的独立验证指标才能恢复展示。
- 评测先合并重复文本关联的问题分组，再划分校准/测试，避免同题别名泄漏；校准仅使用真人文本，用户原文独立评分。

## 样本与方法

两轮各评分 900 条样本：

1. HC3 中文和 M4 中文：300 条真人校准，300 条真人测试，300 条 AI 测试，覆盖问答与技术类标签。
2. CSL 真人技术摘要与项目既有生成记录：300 条真人校准，300 条真人测试，300 条中文科技/科普生成文本测试。生成记录来自 v5 采集，筛选中文、science/technology、finish_reason=stop、route_mismatch=false；原始文件哈希和筛选条件见 `technical-input-provenance.json`。保留了 20 个网关返回的模型名称标签，未独立验证服务商背后的模型身份。

使用种子 20261117，按来源及问题分组的稳定哈希划分校准与测试，再分层限额和去重。用户报告原文不进入校准或批量指标。完整采样清单及逐条评分保存在仓库忽略的 `outputs/text-evaluation-20261117/`，汇总 JSON 随本报告保存。

下表采用统一的 **score > 0.8**，是检测器原始分数的对照，**不包含线上保守判定器的连续高风险片段、覆盖率及动态阈值门控**。

| 测试组 | AI/真人测试数 | 原实现检出率 / 误报率 | 完整覆盖均值检出率 / 误报率 | 完整覆盖取高分检出率 / 误报率 |
| --- | ---: | ---: | ---: | ---: |
| HC3 技术类 | 100 / 100 | 98% / 7% | 98% / 7% | 98% / 8% |
| HC3 问答 | 100 / 100 | 93% / 7% | 93% / 7% | 96% / 29% |
| M4 中文问答 | 100 / 100 | 83% / 3% | 83% / 3% | 84% / 12% |
| 采集科技文本 / CSL | 300 / 300 | 96.33% / 2.67% | 96% / 2.67% | 97% / 21% |

取高分提高少量检出，却明显增加误报，不推荐直接上线。主导语言路由未解决用户样本，也未表现出一致优势。

仅用第二轮 300 条真人校准、目标误报率 2% 计算出的均值策略阈值为 0.9916；对应 300 条 AI 测试检出率为 87.33%，300 条真人误报率为 1%。这些是独立小样本上的观测值和探索阈值，未发布到生产；完整置信区间见 `technical-summary.json`。不能将观测误报率当作产品保证。

## 限制与后续训练判断

- HC3/M4 是否出现在检测器训练数据中未知，成绩可能乐观。
- 第二轮真人主要是技术摘要窗口，AI 为项目采集输出，不严格匹配题目、长度和文体；其结果不能代表用户这种整篇报告的性能。
- 同一个生成模型标签的样本数量较小，不能比较模型排名，也不能证明对未知生成器泛化。
- 单例漏检和总体检出率高可以同时成立。当前实现修复保证输入完整，不保证该例能被识别。

下一阶段优先建立报告级同题、同长度、同文体的真人/AI 样本；按原文档、语义题目及生成模型分组划分训练、验证和全新验收集。用现有漏检与相近真人文本作为难例，先比较成熟检测模型；如果仍然区分不开，再微调现有预训练分类器。用户原文保留为最终回归，不能直接加入训练后再拿它证明成功。

## 复现

在项目依赖环境中运行，不需要调用第三方付费 API：

```bash
git show 2b37c811f7787beba8e570cf4d5bac9b1ef27b30:detection/text_detector.py > /tmp/aigc-legacy-text-detector.py
python -m scripts.evaluate_text_detector \
  --config config.yaml \
  --input data/text_false_positive/normalized/hc3_zh.jsonl \
  --input data/text_false_positive/normalized/m4_multilingual.jsonl \
  --legacy-source /tmp/aigc-legacy-text-detector.py \
  --per-group 100 --seed 20261117 --device cuda:0 \
  --output outputs/text-evaluation-new-run
python -m pytest -q tests
```

第二轮将输入替换为 CSL 和按前述条件映射为 `TextSample` 的采集记录，`--per-group 300`；文本来自 `text`、source_id 来自 `request_key`、partition_id 来自 `prompt.semantic_group_id`、generator 来自 `response_model`，source=`attribution_v5`、domain=`academic_technical`、language=`zh`、label=`ai`、split=`collected`。汇总文件记录了完整参数、输入文件哈希和模型 snapshot 路径。

实际执行环境在 school 的隔离目录 `/tmp/aigc-text-eval-20261117-9Dx7IE`，使用独立 `.venv-validation`，PyTorch 2.6.0+cu124、Transformers 4.50.3、NumPy 1.26.4、scikit-learn 1.5.2。服务器原有环境未升级。
