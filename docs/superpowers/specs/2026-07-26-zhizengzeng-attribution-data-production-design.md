# 智增增文本溯源数据生产设计

## 1. 目标与边界

本阶段只使用智增增 OpenAI 兼容接口生产文本溯源数据。目标是验证十个常见模型
家族是否在受控提示、语言、领域、长度和采样参数下呈现可学习且可复现的差异。

本阶段不把中转站返回的模型名称直接视为已经证实的真实后端身份。数据同时保存
请求路由、响应模型字段、请求编号、采样参数和采集时间；实验结论首先解释为
“智增增指定模型路由的来源识别”，后续再通过跨网关或官方 API 验证真实模型归因。

## 2. 首轮模型家族与固定路由

首轮每个家族只选择一个主模型，全部使用文本 ChatCompletion、非显式思考模式，
不使用 `latest` 或自动路由别名。

| 家族 | 首轮固定路由 | 选择理由 |
|---|---|---|
| OpenAI | `gpt-4o-mini-2024-07-18` | 固定快照、成本低、Chat 参数兼容稳定 |
| Anthropic Claude | `claude-haiku-4-5-20251001` | 固定版本、速度和成本适合批量生成 |
| Google Gemini | `gemini-2.5-flash-lite` | 稳定非预览路由、低成本 |
| DeepSeek | `deepseek-v3.2` | 明确版本、通用文本模型 |
| Alibaba Qwen | `qwen3-30b-a3b-instruct-2507` | 固定 Instruct 版本、非 Thinking 路由 |
| Zhipu GLM | `glm-4.6` | 实测低延迟且稳定；`glm-4.5-flash` 多轮429/超时 |
| MiniMax | `MiniMax-M2.5` | 明确版本、智增增文档列出的文本模型 |
| Moonshot Kimi | `kimi-k2.5` | 稳定显式路由；实测可调用并避免 `kimi-latest` 自动漂移 |
| ByteDance Doubao | `doubao-seed-1-6-flash-250828` | 日期固定的通用 Flash 路由 |
| Xiaomi MiMo | `mimo-v2.5` | 当前文本路由，价格适合批量测试 |

上述十个路由已于 2026-07-26 通过智增增 `/v1/models` 和最小 Chat 请求确认。模型
列表中的 `kimi-k2-0905-preview` 实测返回 404，因此改用可调用的 `kimi-k2.5`；
这说明存在于列表不等于实际调用成功，必须执行逐模型冒烟测试。

## 3. 当前提示词与数据类型

### 3.1 `pilot-v1` 提示词

当前提示词库包含 24 条严格配对提示：

- 语言：中文 12 条、英文 12 条；
- 长度：short、medium、long；
- 领域：science、technology、business、education、health、office、
  literature、history、data_analysis、general；
- 任务：explanation、procedure、comparison、argument、summary、rewrite、
  creative、analysis、data_interpretation、diagnosis、document_writing、
  question_answering。

提示词不询问模型身份，不包含模型厂商名称，不依赖近期新闻，不强制所有回答使用
相同 Markdown 模板。相同 `prompt_id` 必须原样发送给所有模型。

### 3.2 首轮生产的数据

首轮只生产“直接受控生成数据”：

1. 同提示、跨模型配对文本；
2. 中文与英文文本；
3. 短、中、长文本；
4. 十二种任务类型和十个领域；
5. 低随机性与高随机性两种 temperature 采样；为兼容 Claude 并保持跨厂商公平，
   所有模型都省略 `top_p`；
6. 相同条件的独立重复生成；
7. 成功、拒答、截断和错误等运行状态。

正式先导的输出上限为 1536 tokens。该值覆盖约 500 英文词、600 中文字和部分模型的
内部 reasoning token；它是上限而不是目标长度，实际按模型自然停止位置计费。

改写攻击、人类后编辑、翻译链、模型接力生成和主动探针数据不混入首轮训练集，
它们在基础可分性成立后作为鲁棒性或主动指纹数据单独生产。

## 4. 配置文件设计

### 4.1 模型目录

`configs/text_attribution/zhizengzeng_model_catalog.json` 是模型选择的唯一运行入口。
每个模型记录：

- `family_id`、`provider`、`model_id`；
- 是否启用、是否固定版本、是否显式推理；
- API 协议和已验证状态；
- 首轮角色、备用路由和选择备注；
- 首次与最近验证时间。

训练标签使用 `family_id` 和 `model_id` 两级标签，不根据字符串前缀临时推断。

### 4.2 提示词清单

`configs/text_attribution/prompt_manifest.pilot-v1.json` 列出 24 条提示词的 ID、
版本、语言、领域、任务、目标长度和完整文本。Python 提示词库仍是规范源，导出
清单用于审计和服务器交付；测试保证两者完全一致。

### 4.3 运行配置

运行配置分为：

- `smoke.json`：10 模型 × 2 个短提示 × 1 参数 × 1 重复 = 20 请求；
- `local_pilot.json`：10 模型 × 24 提示 × 2 参数 × 2 重复 = 960 请求；
- `server_10k.json`：提示词扩展并冻结到 100 条后，
  10 模型 × 100 提示 × 2 参数 × 5 重复 = 10,000 请求。

运行配置必须显式包含 `max_requests`，实际笛卡尔积超过硬上限时拒绝启动，不能静默
截断正式运行。冒烟测试通过前，后两档配置保持不可执行状态。

## 5. 采集流程

1. 从模型目录读取启用模型，调用 `/models` 验证路由仍存在。
2. 运行 20 请求冒烟，输出到独立 JSONL。
3. 审计每个家族成功率、响应模型字段、耗时、usage、空文本、拒答与截断。
4. 十个家族全部通过后运行 960 请求本地先导采集。
5. 检查类平衡、长度分布、重复度、语言和任务覆盖。
6. 冻结 100 条提示词后，把相同代码、配置和 `.env.local` 上传服务器。
7. 服务器只负责稳定并发采集；两张 4090D 在数据审计完成后用于训练。

请求唯一键包含网关、模型、提示词版本、采样参数和 `repeat_index`。因此同条件重复
可产生多个独立样本，同时断点续采不会重复计费。

## 6. 失败处理与数据质量

- 单个请求失败必须记录到错误 JSONL，不能终止整个大批次；
- 401 立即停止，避免无意义重试；
- 429、5xx 和网络超时采用有界指数退避；
- 空文本、拒答、内容过滤和 `finish_reason=length` 进入质量报告；
- 响应模型与请求模型不一致时保留样本但标为 `route_mismatch`；
- 原始数据只追加写入，清洗结果写到新的 processed 目录；
- API Key 不进入配置 JSON、日志、JSONL 或命令行。

## 7. 验收标准

冒烟阶段：

- 10 个家族均至少成功 2 条；
- 无密钥泄漏；
- 请求和响应模型字段可追踪；
- 无空输出；截断率为 0。

本地先导阶段：

- 目标 960 条，成功率不低于 98%；
- 每个模型、语言、任务和参数组合数量符合配置；
- 训练、验证和测试按 `prompt_id` 分组，无同提示泄漏；
- 生成文本去重后保留率不低于 95%；
- 能输出可直接用于服务器交接的运行清单和质量报告。

## 8. 后续训练决策

960 条数据只用于验证家族可分性和排查捷径，不用于宣称最终溯源效果。完成 10,000
条后先比较字符/字节 n-gram、TF-IDF、冻结多语编码器和观察者语言模型特征。只有
当分组测试、时间外测试和提示外测试均优于简单基线时，才在两张 4090D 上开展
LoRA、监督对比学习、层级分类和开放集拒识训练。
