# 并发溯源数据采集与模型版本替换设计

## 目标

在不破坏现有 JSONL 格式、断点续跑和请求唯一键的前提下，将文本溯源数据采集从严格串行改为有界并发，并在具体模型路由持续失败时及时熔断。同时提供独立的候选模型探测流程，用同一家族内可调用的具体版本替换返回 400/404 的版本。

## 已确认的设计

采集器使用全局线程池，默认 4 个 worker。不同模型可以并发，同一个具体模型始终最多只有一个在途请求。API 请求、退避和重试在工作线程中执行；成功与错误 JSONL 只由主线程追加，因此不需要让多个线程同时写同一个文件。

HTTP 400、403、404 被视为具体模型路由或请求协议不可用：记录触发错误后立即对该具体模型熔断，本轮剩余请求计为 `circuit_skipped`，不再产生付费调用。401 仍是全局认证错误并停止本轮。429、5xx 和无状态网络错误继续按指数退避重试。

空正文使用独立的较小重试上限，默认最多 2 次。单个空正文任务不会立即淘汰模型；同一模型连续两个任务在重试耗尽后仍为空正文，才打开模型熔断。任一成功正文会重置该连续计数。

## 模型版本替换

训练标签保持 `family_id`，具体 API 型号保存在 `request_model`。同一家族使用两个经过验证的不同具体版本是有益的：模型必须学习家族共有的生成风格，而不是记住一个固定版本。

`/models` 返回型号只说明“被列出”，不证明聊天路由可调用。候选版本必须通过独立探测脚本的中文和英文两个短请求，两个请求都有非空正文才标记为 eligible。探测结果写入 JSONL 和汇总 JSON，人工确认后再更新正式模型目录。

首轮只替换确定性失败的型号：

- Kimi：替换返回 404 的 `kimi-k2-turbo-preview`，候选为 `kimi-k2`、`kimi-latest`、`moonshot-v1-8k`。
- MiMo：替换返回 400 的 `mimo-v2-flash`，候选为 `mimo-v2-pro`、`mimo-v2.5-pro`。

Gemini、DeepSeek、GLM 和 MiniMax 的问题涉及隐藏推理 token 或空正文，不与 400/404 混为一类；并发与熔断完成后再用同一探测工具验证非推理版本。

## 输出与兼容性

`RunSummary` 新增 `circuit_skipped`。最终 CLI 汇总和进度日志显示该字段。成功数据结构与原来一致；错误记录增加经过密钥脱敏、长度受限的 `response_body_excerpt`，便于理解 HTTP 400。

旧命令仍能运行。新增参数：

- `--max-workers`，默认 4；
- `--empty-max-attempts`，默认 2；
- `--empty-circuit-threshold`，默认 2。

设置 `--max-workers 1` 可恢复串行行为。

## 验证标准

- 两个不同模型在测试中确实同时执行。
- 同一模型即使全局 worker 大于 1，也从不同时执行两个请求。
- 404 只调用一次 API，后续同模型请求全部熔断跳过。
- 连续两个空正文任务各自最多尝试两次，之后的同模型任务被跳过。
- 并发完成后的成功和错误 JSONL 每行都能独立解析。
- 原有断点续跑、401 停止、429 重试和密钥脱敏测试继续通过。
